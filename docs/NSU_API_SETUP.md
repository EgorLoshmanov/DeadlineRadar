# Подключение API НГУ

DeadlineRadar поддерживает совместимый Chat Completions API НГУ по адресу `https://deepcode.ci.nsu.ru/api/chat/completions`. Нужен действующий API-ключ, выданный для доступа к этому сервису. Наличие настройки само по себе не подтверждает доступ к API или модели.

## Локальная настройка

Выполняйте команды из каталога проекта с активированным виртуальным окружением. Если `.env` ещё нет, создайте его командой `cp .env.example .env`. Существующий файл не перезаписывайте: измените в нём только нужные значения.

```dotenv
LLM_PROVIDER=openai
LLM_API_KEY=
LLM_MODEL=Qwen3.8-27B
LLM_API_URL=https://deepcode.ci.nsu.ru/api/chat/completions
LLM_TIMEOUT=2.5
LLM_CHAT_TEMPLATE_KWARGS={"enable_thinking":false}
LLM_CA_BUNDLE=
```

В `LLM_API_KEY` вставьте локально сам ключ, без кавычек и без слова `Bearer`. Бот добавляет заголовок авторизации автоматически. `.env` исключён из Git; не публикуйте его и не отправляйте ключ в переписке.

Значение `openai` в `LLM_PROVIDER` обозначает формат совместимого API. Оно не означает прямое подключение к сервису OpenAI: получатель запроса определяется `LLM_API_URL`, здесь это НГУ. Пустое `LLM_CA_BUNDLE` использует системные доверенные центры сертификации. Отдельный PEM-файл нужен только для окружения, где он действительно требуется.

`LLM_CHAT_TEMPLATE_KWARGS` — необязательный JSON-объект. Допустимы только ключи `thinking` и `enable_thinking` со значениями `true` или `false`; другие поля и значения отклоняются при проверке конфигурации. Для `Qwen3.8-27B` значение `{"enable_thinking":false}` передаётся как поле `chat_template_kwargs` запроса и отключает этап рассуждений для быстрого формирования JSON. Эта комбинация прошла проверку API НГУ. Время ответа зависит от нагрузки и сети; отключение рассуждений не гарантирует соблюдение бюджета при каждом запросе. Если переменная отсутствует или пуста, дополнительные параметры шаблона не передаются.

Переменные, уже заданные в окружении терминала, имеют приоритет над `.env`. При переходе с другого API обновите и их, если они были заданы.

## Проверка и запуск

```bash
python main.py --check-llm
```

Команда выполняет реальный запрос к выбранной модели и проверяет распознанный результат. Она не открывает БД, не обращается к Telegram, не запускает бот и не требует `BOT_TOKEN`. Успех подтверждается сообщением «Проверка LLM пройдена». Без действующего ключа, доступной модели и сетевого доступа к сервису подтвердить работу нельзя.

Общий бюджет распознавания — не более 2.5 секунды. Если API не ответил вовремя, вернул ошибку или ненадёжный результат, обычный бот использует локальный парсер, затем при необходимости ручной ввод. Для отдельной проверки такой fallback не считается успешным ответом модели.

После изменения `.env` остановите работающий бот через `Ctrl+C` и запустите его заново:

```bash
python main.py
```

Для обычного запуска в `.env` также нужен токен Telegram-бота `BOT_TOKEN`. Оставьте только один работающий процесс этого бота.

## Переключение модели

Основная модель в примере — `Qwen3.8-27B`. Список доступных моделей зависит от вашего ключа и конфигурации сервиса. Получите актуальный идентификатор модели у администратора НГУ из списка моделей, доступных вашему ключу (`GET /api/models`). Используйте точное значение идентификатора в `LLM_MODEL`, включая регистр и префикс, если он есть.

Ошибка HTTP 400 с сообщением `Model not found` означает, что заданное имя не найдено или модель недоступна для этого доступа. Проверьте `LLM_MODEL` по актуальному списку. В частности, прежний пример `deepseek-ai/DeepSeek-V4-Flash-0731` при проверке не был доступен, хотя ключ давал доступ к списку моделей. Выбирать DeepSeek следует только после подтверждения доступного имени для вашего ключа; работа этой модели в НГУ здесь не подтверждена.

При переходе на другую модель очистите `LLM_CHAT_TEMPLATE_KWARGS`, если её поддержка параметров Qwen не подтверждена администратором. Повторите `python main.py --check-llm`, затем перезапустите бот. Провайдер, URL и ключ при переключении моделей в том же сервисе НГУ остаются прежними.
