# DeadlineRadar

Telegram-бот для учебных дедлайнов. Студент пересылает сообщение с заданием, проверяет распознанные предмет, работу и срок и сохраняет карточку. Бот показывает личные и групповые задания, напоминает о сроках и хранит историю сданного.

Проект реализован на Python 3.11+, aiogram 3, APScheduler и SQLite. Для распознавания можно бесплатно подключить GigaChat API для физлиц; без ключа работают локальные правила и ручное добавление. Подключение Anthropic Messages API также сохранено для существующих настроек.

## Быстрый запуск

Выполняйте команды из каталога проекта. Для Telegram-режима нужны интернет и токен бота, созданного через [@BotFather](https://t.me/BotFather).

```bash
python3 -m venv .venv
source .venv/bin/activate
python -m pip install -r requirements.txt
```

Если `.env` ещё нет, создайте его командой `cp .env.example .env`. Существующий файл не перезаписывайте. В Windows PowerShell окружение активируется командой `.venv\Scripts\Activate.ps1`; новый файл настроек можно скопировать командой `Copy-Item .env.example .env`.

Откройте `.env` и заполните `BOT_TOKEN`. Затем:

```bash
python main.py --check
python main.py
```

`--check` проверяет конфигурацию и доступность SQLite без обращения к Telegram, без токена и без запроса к внешней модели. При необходимости создаётся файл БД. Обычный запуск начинает long polling и планировщик напоминаний. Оставьте процесс работающим, откройте личный диалог со своим ботом и отправьте `/start`. Для остановки нажмите `Ctrl+C`.

Для распознавания через бесплатный облачный API следуйте [инструкции подключения GigaChat](docs/GIGACHAT_SETUP.md). Она описывает получение ключа через Сбер ID, настройку `.env` и отдельную проверку модели. Покупать подписку для Freemium не требуется; он предназначен для личного некоммерческого использования.

## Демонстрация без токенов и интернета

Ядро проекта использует стандартную библиотеку Python. Для локальной демонстрации установка Telegram-зависимостей не нужна:

```bash
python run_test.py
```

Демонстрация использует временную БД и резервный парсер: она не отправляет сообщения реальным пользователям и не изменяет рабочий файл `deadlines.db`.

После установки зависимостей полный набор проверок, включая обработчики Telegram на имитации API, запускается командой:

```bash
python -m unittest discover -s tests -v
```

Заполнить отдельную БД демонстрационными заданиями:

```bash
python seed.py --database demo.db --user-id 1001
```

Идентификатор `1001` используется для офлайн-примера. Чтобы увидеть демоданные в Telegram, укажите собственный числовой Telegram ID и настройте `DATABASE_PATH=demo.db` перед запуском бота. Не добавляйте демонстрационные записи в рабочую БД команды.

## Настройки

Настройки берутся из `.env`; уже заданные переменные окружения имеют приоритет. `.env`, файлы БД и виртуальное окружение исключены из Git.

| Переменная | Назначение | По умолчанию |
| --- | --- | --- |
| `BOT_TOKEN` | Токен Telegram-бота; обязателен для обычного запуска | пусто |
| `DATABASE_PATH` | Файл SQLite; относительный путь считается от каталога проекта | `deadlines.db` |
| `APP_TIMEZONE` | Общий часовой пояс студентов и групп в формате IANA | `Asia/Novosibirsk` |
| `LLM_PROVIDER` | Внешний сервис: `gigachat` или `anthropic` | в новом `.env.example`: `gigachat` |
| `LLM_API_KEY` | Необязательный ключ; для GigaChat нужен Authorization Key из Studio | пусто |
| `LLM_MODEL` | Идентификатор модели, доступной в вашем аккаунте | в новом `.env.example`: `GigaChat-2` |
| `LLM_API_URL` | HTTPS-адрес генерации выбранного провайдера | в новом `.env.example`: `https://api.giga.chat/v1/chat/completions` |
| `LLM_TIMEOUT` | Бюджет внешнего распознавания; максимум 2.5 с, старые значения до 5 с ограничиваются 2.5 с | `2.5` |
| `LLM_CA_BUNDLE` | Путь к доверенным CA для TLS; относительный путь считается от каталога проекта | в новом `.env.example`: `certs/russian_trusted_root_ca.pem` |
| `SCHEDULER_INTERVAL` | Период проверки напоминаний, от 5 до 300 секунд | `30` |
| `LOG_LEVEL` | `DEBUG`, `INFO`, `WARNING`, `ERROR` или `CRITICAL` | `INFO` |

Для GigaChat задайте значения из [инструкции](docs/GIGACHAT_SETUP.md). Authorization Key храните только локально в `.env`: не отправляйте его в чат и не добавляйте в Git. Для внешнего распознавания одновременно нужны `LLM_API_KEY` и `LLM_MODEL`. Если одно из полей пусто, запросы к модели не выполняются. Исходный текст задания отправляется внешнему сервису только при включённой интеграции.

Старые `.env` без `LLM_PROVIDER` сохраняют режим Anthropic; чтобы перейти на GigaChat, явно замените все настройки `LLM_*` по инструкции. Подписка на пользовательский чат и доступ к API — разные способы доступа.

Внешнее распознавание ограничено общим бюджетом 2.5 секунды, включая OAuth, запрос и проверку ответа. При тайм-ауте, сетевой ошибке, некорректном JSON или низкой уверенности бот использует резервный парсер. У API GigaChat для физлиц один одновременный поток: если он занят другим запросом этого процесса, бот сразу использует локальные правила. OAuth-токен переиспользуется до истечения его срока, максимум 30 минут. Лимит ожидания не гарантирует реальную задержку сервиса или качество распознавания: для этого нужна проверка с действующим ключом.

SQLite хранит дату как локальное время в формате `YYYY-MM-DD HH:MM`. Выберите `APP_TIMEZONE` до начала работы. Для существующей БД смена часового пояса требует отдельной миграции дат: простая замена переменной может изменить фактический момент напоминания. Индивидуальные часовые пояса в этой версии не предусмотрены.

## Использование

Подробные сценарии приведены в [руководстве пользователя](docs/USER_GUIDE.md).

| Команда | Действие |
| --- | --- |
| `/start` | Начало работы и главное меню |
| `/help` | Справка |
| `/deadlines` | Активные личные и групповые дедлайны |
| `/history` | Сданные задания |
| `/add` | Ручное добавление: предмет → задание → дата |
| `/group` | Учебные группы, приглашения и доступные действия |
| `/newgroup Название` | Создать группу и стать её старостой |
| `/join CODE` | Вступить по коду приглашения |
| `/publish` | Начать публикацию дедлайна в свою группу |
| `/settings` | Настройки доставки напоминаний и новых заданий группы |
| `/plan` | Учебный план, расход квоты и бесплатное переключение |
| `/cancel` | Отменить текущий ввод или черновик |
| `/delete_me` | Удалить данные после подтверждения |

Бот работает в личных диалогах. Учебная группа — сущность внутри приложения: добавлять бота в общий Telegram-чат не требуется. Создатель группы получает роль старосты. Он публикует общие задания, а каждый участник отмечает свою сдачу независимо.

Пример сообщения:

```text
лаба 3 по БД до пятницы
```

Резервный парсер определит предмет «Базы данных», задание «Лабораторная работа №3» и ближайшую пятницу. Результат появится в карточке предварительного просмотра. Сохранение выполняется только по кнопке; предмет, задание и дату можно исправить до подтверждения.

## Устройство проекта

```text
main.py                Запуск, проверка конфигурации, планировщик
bot.py                 Команды, кнопки и диалоги Telegram
config.py              .env, общий часовой пояс, границы семестра
parser.py              Очистка текста, внешний и резервный парсеры
models.py              Валидация подтверждённой карточки
services.py            Подготовка и сохранение дедлайна
db.py                  SQLite, права доступа, группы и журнал доставки
notifications.py       Отправка напоминаний с защитой от повторов
publications.py        Очередь рассылки новых заданий группы
plans.py               Учебные планы и лимит активных задач
presentation.py        Карточки, даты и списки
run_test.py            Автономная демонстрация на временной БД
seed.py                Демонстрационные данные
tests/                 Автоматические тесты
docs/USER_GUIDE.md      Руководство пользователя
docs/GIGACHAT_SETUP.md  Бесплатный облачный API: доступ, настройка и проверка
```

Реализация уточняет несколько деталей, не полностью заданных в исходной схеме:

- Сдача общего задания хранится отдельно для каждого участника в `deadline_completions`. Отметка одного студента не скрывает задание у остальных.
- Статус `pending` / `completed` вычисляется для конкретного участника. Роль старосты определяется владельцем каждой группы: один пользователь может быть старостой в одной группе и студентом в другой.
- Таблица `group_members` задаёт доступ к групповым дедлайнам. Личные задания видит только их владелец; публиковать и удалять задания группы может её староста.
- В `reminder_deliveries` сохраняется резерв доставки с уникальным ключом владельца. Перед сетевым запросом в `reminder_attempts` записывается попытка для задания, пользователя и окна. Это предотвращает повтор после потери ответа Telegram, аварии и перезапуска. Просроченный резерв можно восстановить только до начала отправки.
- У подтверждаемого черновика есть ключ повторного сохранения. Повторный клик не создаёт копию того же дедлайна.
- Даты валидируются перед сохранением. Если срок нельзя определить уверенно, бот запрашивает ручной ввод; расписание учебных пар не предполагается.
- Просроченные несданные задания остаются в активном списке. Очистка старой истории не удаляет групповое задание, которое ещё нужно хотя бы одному действующему участнику. У старой сдачи такого задания удаляется дата (`completed_at = NULL`), сохраняется только признак «сдано»: он исключает задание из личного активного списка и дальнейших напоминаний. История показывает только датированные сдачи текущего семестра.

SQLite использует внешние ключи, параметризованные запросы, транзакции и режим WAL. Пользовательские строки экранируются при показе карточек в Telegram. Секреты хранятся вне исходного кода.

## Учебные планы и лимиты

По умолчанию действует `free`: не более 15 активных задач, созданных пользователем. В квоту входят личные и опубликованные им групповые задания. Общее задание занимает слот, пока оно не сдано всеми текущими участниками; входящие задания других старост не расходуют квоту получателя. Просроченные несданные задания остаются активными. Повторное подтверждение того же черновика не расходует дополнительный слот.

В `/plan` показаны текущий план и расход квоты. Кнопки или команды `/plan free`, `/plan student`, `/plan group` переключают локальные учебные планы без оплаты. `student` и `group` снимают лимит; владение группой по-прежнему определяет права старосты. Возврат на `free` не удаляет существующие задачи: пока активных 15 или больше, новые не сохраняются. Черновик при отказе сохраняется, его можно подтвердить после освобождения слота или смены плана.

Для всех планов сохранены два напоминания, за 3 и за 1 день, согласно конкретному ТЗ. Тарифная гипотеза с одним напоминанием не применяется к учебному MVP.

## Рассылка публикаций

После подтверждения старостой нового задания в SQLite атомарно сохраняются задание и очередь для текущих участников группы, кроме автора. Бот сразу запускает доставку сообщения с предметом, заданием, сроком и кнопкой «Я сдал». Автор получает подтверждение сохранения. Участники, вступившие позднее, видят задание в списке и получают обычные напоминания, без задней рассылки публикации.

Неотправленная очередь восстанавливается при запуске и проверяется планировщиком. Перед отправкой повторно проверяются членство, настройки уведомлений, срок и сдача. `/settings` управляет и напоминаниями, и сообщениями о публикациях. Старые задания при обновлении не создают новую рассылку.

Попытка записывается до запроса Telegram. При потере ответа или остановке после начала запроса публикация не повторяется; при таком сбое сообщение может быть пропущено. Подтверждённый отказ `RetryAfter` разрешает повтор после указанной задержки. Сообщение о публикации — отдельное событие, оно не расходует два окна напоминаний.

## Приоритет распознавания

При настроенной модели каждый допустимый текст сначала передаётся LLM. После ответа проверяются структура, поля, номера работ и дата. Однозначная календарная дата проверяется независимо; при нескольких явно заданных датах модель может выбрать исправленный срок, например «не до 15 октября, а до 16 октября». Ошибочный ответ, низкая уверенность, отсутствие срока или сбой API приводят к локальному разбору. Если и он не даёт надёжного срока, бот просит ручной ввод. Неполное время и неизвестное расписание пар не дополняются догадкой модели. Общий бюджет остаётся 2,5 секунды.

## Напоминания и ограничения

- Для каждого несданного задания предусмотрены два окна: от 72 до более чем 24 часов до срока и последние 24 часа до срока. В текущем окне отправляется одно напоминание. Если задание добавили поздно или бот был выключен, устаревшее окно не воспроизводится.
- Проверка выполняется с интервалом `SCHEDULER_INTERVAL`, поэтому время отправки не гарантируется с точностью до секунды. После отметки «Я сдал» дальнейшие напоминания этому студенту прекращаются.
- Процесс бота должен работать и иметь доступ к Telegram. Неопределённый результат отправки (обрыв связи, тайм-аут или остановка во время запроса) расходует окно без повтора. Так сохраняется предел двух фактических напоминаний на пользователя и задание. При сбое после записи попытки возможен пропуск уведомления. Повтор разрешён лишь после подтверждённого отказа без доставки, например `RetryAfter`, с соблюдением указанной задержки.
- При первом запуске обновлённой версии SQLite автоматически мигрирует прежнюю схему без удаления заданий. Старые записи `claimed` / `retry` консервативно считаются неопределёнными попытками: предыдущая версия уже могла отправить сообщение без получения ответа. Эти окна не повторяются; следующее независимое окно остаётся доступным. Старые подтверждённые доставки также сохраняются.
- Текст распознавания ограничен 1000 символами; предмет — 120, задание — 500. HTML удаляется до распознавания, а ограничение длины проверяется по исходному сообщению.
- Дата без времени означает `23:59`. Дата без года относится к текущему году и не переносится автоматически в следующий. «Следующая пятница» означает пятницу следующей календарной недели, «ближайшая пятница» — ближайшее будущее в выбранном часовом поясе.
- «В полдень» означает `12:00`, «в полночь» — `00:00` указанного дня. «Утром», «вечером» и «до обеда» без точного времени требуют уточнения. Номера упражнений и диапазоны задач не принимаются за даты.
- Явные составные номера работ (`№2.1`) сохраняются целиком. Если внешняя модель теряет номер задания или упражнения, её ответ заменяется локальным разбором. Номер группы и календарный день не входят в эту проверку.
- Прошлая пятница и уже прошедший день явно указанной текущей недели не переносятся в будущее. Длительность выполнения («займёт 2 часа») сохраняется в задании и не становится временем сдачи.
- Если возле срока указан другой часовой пояс (МСК, UTC, числовой сдвиг), бот просит уточнить время в часовом поясе приложения. Автоматическая конвертация и относительный срок «через N часов» не поддерживаются; укажите точную локальную дату и время.
- «К паре 15 числа», дата без месяца, несуществующая или прошедшая дата требуют ручного уточнения. Учебное расписание и OCR изображений не подключены; для распознавания нужен текст сообщения.
- Черновики и шаги диалога хранятся в оперативной памяти. Перезапуск сбрасывает незавершённый ввод; подтверждённые задания, группы, отметки сдачи и журнал напоминаний сохраняются в SQLite.
- При удалении аккаунта старосты удаляются и созданные им группы с общими заданиями. Участники должны учитывать это перед подтверждением удаления.

Для резервного копирования остановите бот и сохраните файл SQLite. Для копии без остановки используйте SQLite Backup API; простое копирование одного `.db` при активном WAL может пропустить ещё не перенесённые записи. Настройки и секреты храните отдельно от общедоступных копий.
