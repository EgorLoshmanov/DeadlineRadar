# Подключение бесплатного GigaChat API

Для учебной демонстрации DeadlineRadar можно использовать GigaChat API Freemium для физических лиц. Платная подписка на чат или покупка пакета токенов для этого не требуется. Без ключа бот продолжает работать через локальные правила и ручное добавление.

## 1. Получите бесплатный доступ

1. Откройте [официальную инструкцию регистрации](https://developers.sber.ru/docs/ru/gigachat/quickstart/ind-create-project) и перейдите по ссылке личного кабинета Studio.
2. Войдите через свой Сбер ID.
3. Нажмите **Создать проект**, выберите **GigaChat API** в разделе **AI-модели**.
4. Укажите название, например `DeadlineRadar`, и примите пользовательское соглашение.
5. Проверьте в проекте тариф **Freemium** и Scope **GIGACHAT_API_PERS**. По официальной инструкции Freemium подключается новым пользователям по умолчанию.

По [официальным тарифам для физлиц](https://developers.sber.ru/docs/ru/gigachat/tariffs/individual-tariffs), обновлённым 7 октября 2026 года, Freemium включает 365 млн токенов на 12 месяцев: 250 млн Lite, 40 млн Pro, 25 млн Max и 50 млн Ultra. Для приведённых ниже настроек используется Lite `GigaChat-2`. Остаток и действующие условия проверяйте в своём кабинете: тарифы могут меняться.

Freemium разрешён **только для личного некоммерческого использования**. Для коммерческого использования нужен платный пакет; это отдельный этап за пределами данной учебной настройки. См. [условия коммерческого использования](https://developers.sber.ru/docs/ru/gigachat/tariffs/commercial). Не переходите к покупке токенов для выполнения этой инструкции.

## 2. Скопируйте Authorization Key

1. В созданном проекте откройте **Настройки API**.
2. Нажмите **Получить ключ**.
3. Сохраните значение поля **Authorization Key** локально. Ключ показывается один раз; подробнее — [начало работы с API](https://developers.sber.ru/docs/ru/gigachat/quickstart/ind-using-api).

Приложению нужен именно готовый **Authorization Key**, а не Client ID, Client Secret или Access token. Готовый ключ уже имеет нужную кодировку: не кодируйте его повторно и не добавляйте к нему префикс `Basic`.

Не присылайте ключ в переписку, не показывайте на скриншотах и не помещайте в исходники. При утрате или раскрытии создайте новый ключ в Studio.

## 3. Заполните локальный `.env`

Все команды выполняйте из каталога `DeadlineRadar`. Если файла `.env` ещё нет, скопируйте шаблон:

```bash
cp .env.example .env
```

Существующий `.env` не перезаписывайте. Откройте его в редакторе и задайте:

```dotenv
LLM_PROVIDER=gigachat
LLM_API_KEY=вставьте_готовый_Authorization_Key
LLM_MODEL=GigaChat-2
LLM_API_URL=https://api.giga.chat/v1/chat/completions
LLM_TIMEOUT=2.5
LLM_CA_BUNDLE=certs/russian_trusted_root_ca.pem
```

Замените текст `вставьте_готовый_Authorization_Key` своим ключом целиком. Для обычного запуска бота также заполните `BOT_TOKEN` из BotFather. Для проверки только LLM токен Telegram не нужен.

`.env` исключён из Git. Уже заданные переменные окружения имеют приоритет над `.env`: если сервис выбирается неправильно, проверьте, не задан ли другой `LLM_PROVIDER`, `LLM_API_URL` или ключ в окружении терминала/IDE. Не выводите значения секретов в лог. После изменения настроек перезапустите процесс бота.

В старых `.env`, где `LLM_PROVIDER` не указан, сохраняется режим Anthropic. Для перехода задайте все шесть строк выше, включая провайдера и URL.

### Доверенный сертификат

GigaChat использует сертификаты НУЦ Минцифры. В проект включён публичный корневой сертификат `certs/russian_trusted_root_ca.pem`; его источник, срок действия и отпечаток указаны в [описании сертификата](../certs/README.md). Переменная `LLM_CA_BUNDLE` указывает на этот PEM-файл; относительный путь считается от каталога проекта. Это сертификат доверия, он не содержит ключа аккаунта.

При ошибке TLS сначала проверьте наличие файла и правильность пути. Если в вашей копии проекта сертификата нет, получите его по ссылке из [официальной инструкции GigaChat](https://developers.sber.ru/docs/ru/gigachat/certificates) и укажите путь к PEM-файлу. Не подменяйте проверку сертификатов отключением TLS-валидации. Приложение использует указанный CA bundle без изменения системного хранилища доверия.

## 4. Проверьте именно облачную модель

Активируйте виртуальное окружение и выполните:

```bash
python main.py --check-llm
```

Команда отправляет только несекретную тестовую фразу:

```text
Лаба 3 по БД до пятницы в 18:00
```

Она не обращается к Telegram, не запускает polling, не читает и не изменяет рабочую БД. Успех с кодом выхода `0` означает, что внешний API вернул результат, прошедший проверки парсера. Отсутствующий ключ, ошибка доступа, тайм-аут, отказ модели или непригодный ответ дают сообщение **«LLM не подтверждён»** и код выхода `1`. Локальный резервный парсер не маскирует неудачу этой проверки.

Это отдельная проверка от `python main.py --check`: обычный `--check` проверяет настройки и SQLite, может создать БД и не подтверждает доступ к внешней модели. Сетевой `--check-llm` расходует небольшое количество бесплатных токенов. До его успешного выполнения работа внешней интеграции с вашим аккаунтом не подтверждена.

После успешной проверки запустите бот:

```bash
python main.py
```

Отправьте сообщение с заданием в личный диалог, проверьте предмет, название и дату в предварительной карточке и только затем сохраните.

## 5. Учитывайте бюджет времени и резервный режим

Общий бюджет внешнего распознавания ограничен 2.5 секунды: в него входят получение OAuth-токена, сетевой запрос, разбор и проверка результата. После исчерпания бюджета приложение использует локальные правила; при недостаточных данных попросит ручное уточнение. Этот запас предназначен для требования обработки сообщения за 3 секунды на уровне парсера. Он не является обещанием задержки облачного сервиса или доставки ответа Telegram.

Для [физлиц разрешён один одновременный поток](https://developers.sber.ru/docs/ru/gigachat/limitations). Пока GigaChat обрабатывает другой запрос данного процесса, новый запрос сразу переходит к локальному парсеру. Не запускайте несколько экземпляров бота с одним ключом: локальный контроль занятости действует внутри одного процесса.

Приложение само обменивает Authorization Key на OAuth Access token и переиспользует его до окончания срока действия, максимум 30 минут. Вручную обновлять Access token и сохранять его в `.env` не нужно. Схема описана в [документации авторизации API](https://developers.sber.ru/docs/ru/gigachat/api/reference/rest/gigachat-api).

Для полного локального режима оставьте строку `LLM_API_KEY=` пустой и перезапустите процесс. Внешних запросов распознавания тогда не будет. Качество извлечения дат и фактическая задержка выбранной модели требуют проверки на ваших примерах; любой результат перед сохранением подтверждает пользователь.
